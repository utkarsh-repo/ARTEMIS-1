# Capability Parity Matrix: Cairn + ARTEX → ARTEMIS

This is a working, source-backed matrix rather than a claim of complete parity. Cairn's inspected architecture emphasizes a shared Fact/Intent/Hint graph, a dispatcher as the sole protocol writer, task classes (`bootstrap`, `reason`, `explore`), worker/container lifecycle and leases. ARTEX's inspected sources/docs cover a planner-worker exploration loop, separate asset and exploration graphs, anchor relationships, persisted activity/trace capture, task dependencies, finding workflow, traffic capture/binding, MCP integrations, interception/approval, operator UI and PostgreSQL-backed persistence.

## ARTEMIS v2.2.8 delta

The legacy deterministic HTTP client calls `InlineRequestAuthorizationGateway` before each request. It rechecks the loaded policy digest, enforces host/path/method scope and limits the legacy path to GET/HEAD/OPTIONS. It also rejects Host/authority and auth/transport/method-override headers, header injection and bodies on read-only requests before transport; transport-level DNS validation, IP pinning, TLS verification and redirect disabling remain independent defenses. Queue-bound exact-action approval is still not wired to the legacy engine, and broader prompt-injection end-to-end tests remain open, so the parent authorization requirement remains in progress.

Added `ScopedEgressPolicy` and a CONNECT-only broker that checks exact hosts/ports, live assessment/policy context, all DNS answers, explicit private-CIDR exceptions and signed pinned-IP decisions. Added a dry-run-first nftables generator that drops other traffic from a dedicated worker subnet. These are supported components, not a deployed network boundary: no rules were applied and the worker remains `--network=none` until real-runtime and host-firewall integration tests pass. The supervisor now verifies the local image digest before launch and attempts forced container removal during termination. Approval expiry/state is checked again before execution and result commit.

## ARTEMIS v2.2.7 delta

Added `ContainerWorkerSupervisor` for a fixed entrypoint in a SHA-256-pinned image. The command applies no-network, read-only root, non-root UID, dropped capabilities, no-new-privileges, bounded CPU/memory/PIDs/tmpfs, capped input/output, timeout, and explicit container/process termination. It refuses network-required actions until an externally enforced scoped egress proxy exists. The environment has no working Docker/Podman/bubblewrap/Firejail runtime (Linux network namespace creation is denied), so fake-runtime tests verify command construction and supervisor lifecycle only; real isolation and queue cancellation integration remain unverified.

## ARTEMIS v2.2.6 delta

Verified asset-conflict semantics, bounded trace search and explicit proxy rejection; added chained evidence manifests, verified export and archive-before-delete retention; startup reconciliation; append-only retest history; explainable planner scoring; local health and backup/restore; a sanitized benchmark corpus/evaluator; and a loopback-only authenticated operator API. The operator API uses server-side bearer-token identity/role configuration and does not support remote binds, TLS termination or an external identity provider. The independent verifier is not yet executed by a trusted checker, and the worker isolation/dispatch boundary remains the principal blocker.

## Historical ARTEMIS v2.2.3 delta

At v2.2.3, a closed-world `http_request` schema (GET/HEAD/OPTIONS, configured auth-profile reference, bounded response bytes) is validated at approval request, consumption and queued-action authorization. `AuthorizationGateway` binds a claimed task to current policy/scope, exact arguments, tool version, unique action ID, approval identity and expiry; it atomically consumes approval and writes an execution authorization record. Runtime events are hash-chained and verifiable, and approval revocation is checked again before entering the running state. This is still not end-to-end tool execution: no isolated handler backend exists, the legacy engine is not wired to this queue, and the authenticated operator API remains missing.

## Audit limits and license notes

- Direct Git clone/network DNS was unavailable in the execution container. Source files above were retrieved through the connected GitHub source interface; a complete recursive file-by-file and test-by-test audit remains open.
- ARTEX README identifies AGPL-3.0 and includes additional usage restrictions; Cairn README describes AGPL-3.0 and commercial-license terms. No source code has been copied into ARTEMIS in this batch. Obtain legal review before reusing source or asserting license compatibility.
- “Missing” is not an exclusion. All unimplemented capabilities remain tracked in `requirements-register.md` until verified, blocked with a concrete reason, or formally excluded.
